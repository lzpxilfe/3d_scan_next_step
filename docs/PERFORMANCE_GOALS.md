# 성능 목표 — 상용 3종 대비 "명확히 더 나음" (D-2026-10-12-06)

작성일: 2026-10-12. 관련: [결정](DECISIONS.md) · [검증 요구](../05_ACCURACY_DATA_AND_VALIDATION.md) ·
[런기록](../src/archphoto/runlog/record.py) · [독립 검증](../src/archphoto/quality/) · [R01](../src/archphoto/recon/)

## 1. 목표와 정직한 성격

**목표 [U]:** Metashape·Pix4D·RealityCapture보다 **명확히 더 나아야** 한다. 1순위 지표는
**① 속도 ② 정밀도·정직성**, 검증은 **공개 벤치마크 대조**.

> 이 문서의 "더 낫다"는 **증명해야 할 목표이지 확인된 사실이 아니다.** 수치가 나오기 전까지
> 우위를 주장하지 않는다(AGENTS: 미검증 성능을 확정으로 말하지 않기). 아래 기준은 이 목표를
> **반증 가능**하게 만드는 장치다.

## 2. 지표별 "명확히 더 낫다"의 정의 (반증 가능해야 함)

### 2.1 정밀도·정직성 (1순위)
| 하위 지표 | 측정 방법 (코드 계약) | "명확히 우위" 판단 근거 |
|---|---|---|
| 독립 검증점 좌표·높이 오차 | `quality.evaluate_check` 잔차(중앙값·상위 백분위) | 동일 공개 자료에서 상용/문헌 보고 오차보다 작음 |
| 독립 치수 오차 | CHECK_LENGTH 기준 길이 오차 | 기준척 대비 치수 오차가 더 작음 |
| 관측/보간 정직성 | `archaeo.surface.SurfaceKind`로 관측·보간·전시 구분 표기 | 상용은 보간/평활을 사실처럼 제시, 본 제품은 명시 구분 → **정직성 우위는 능력 차원** |
| 검증점 독립성 | `PointUsageLedger`로 보정 재사용 원천 차단 | GCP/검증점 분리가 코드로 강제됨 |

정직성(관측/보간·실측/전시 구분, 검증점 독립성)은 상용이 대체로 제공하지 않는 **정성 우위**로,
수치 오차와 함께 보고한다. 오차만으로 설명하지 않는다(05 §8).

### 2.2 속도 (1순위)
| 하위 지표 | 측정 방법 | "명확히 우위" 판단 근거 |
|---|---|---|
| 전체 처리 시간 | `RunRecord.resources.wall_seconds` | 자기 하드웨어 명시 조건에서 동등 품질 기준 비교 |
| 단계별 시간 | R01 단계(깊이·시점선택·정밀화·융합·메시)별 소요 | 중복 계산 감소가 실제 시간 단축으로 이어짐 |
| 자원 | 최대 RAM·VRAM·디스크 (`RunRecord.resources`) | 상용 대비 소형 장비(GTX 1060급)에서 가용 |

### 2.3 재현성·하드웨어 불특정 (속도 외 추가 정성 우위 축)

상용 3종이 쉽게 주지 못하는 **하드웨어 무관한 결과 + 하드웨어 불특정 실행**을 우위로 만든다.

| 하위 지표 | 정의·측정 방법 | 성격 |
|---|---|---|
| 결과 재현성(결정론) | 같은 입력·같은 버전이면 메시가 허용오차 안에서 동일. RANSAC·최적화 **난수 시드 고정**, 연산 순서 결정론 고정, 엔진·코드·가중치 버전 기록(`RunRecord`) | 하드웨어 무관(형상) |
| 알고리즘 복잡도 감소 | R01이 처리할 시점-쌍·픽셀 수 감소량 (연산량 지표) | 하드웨어 무관(알고리즘 속성) |
| 하드웨어 불특정 실행 | **CPU 폴백 경로** 제공, CUDA 락인 없음, 크로스 플랫폼 | 접근성(이식성) |

> 주의: **벽시계 속도는 하드웨어에 묶인다.** 이 축은 속도를 대체하는 게 아니라, 속도 경쟁이
> 성립하지 않는 지점에서 "재현 가능 + 어디서나 실행 + 오픈소스"를 정성 우위로 확보하는 장치다.
> 형상 재현성은 허용오차 기준으로, 이식성은 CPU 폴백 동작 증거로 판단한다.

## 3. 비교 검증 방법 — 공개 벤치마크 대조와 그 한계 [D·O]

방법 **[U]: 공개 벤치마크 대조**(상용 도구 직접 설치 없이). 대상 후보: ETH3D, Tanks&Temples,
DTU 등 ground-truth 있는 공개 MVS/재구성 벤치마크.

**정직하게 밝혀야 할 한계:**
- 공개 학술 벤치마크는 주로 **알고리즘**을 비교하며, 상용 3종(RealityCapture 등)의 점수가
  항상 실려 있지는 않다. → "상용보다 정밀"을 공개 벤치마크만으로 단정하기 어렵다.
- **속도**는 하드웨어·설정 의존적이라 문헌 수치와 직접 비교는 신뢰성이 낮다. → 속도는
  **자기 하드웨어에서 실행 시간을 명시**하고, 상용의 공개 자료/문헌 수치는 참고치로만 쓴다.
- 공개 벤치마크는 고고학 특유(토층·얇은 구연·석기 날)를 항상 포함하지 않는다. → 형상 보존은
  별도 고고학 시험 대상(05 §7)으로 평가한다.

따라서 현실적 검증 구성 **[D]:**
1. **정밀도:** 공개 벤치마크에서 ground-truth 대비 오차(본 제품)를 측정하고, 상용/선행 연구
   보고치와 대조. 상용 점수가 없으면 "공개 SOTA 수준 이상"으로 표기하고 상용 우위는 유보.
2. **속도:** 자기 하드웨어(GTX 1060 목표)에서 실행 시간을 기록하고, R01 on/off로 개선폭을
   측정. 상용 절대 시간과의 비교는 근거 수준을 명시(참고치 vs 실측 구분).
3. **정직성:** 관측/보간·실측/전시 구분과 검증점 독립성을 **능력으로** 문서화(수치 경쟁 아님).

## 4. 수락 기준 (숫자는 미정 [O], 형식만 확정)

- [ ] 독립 검증점 오차(중앙값·95%)를 공개 벤치마크 ground-truth 대비로 보고했다.
- [ ] 상용/문헌 대조치의 **출처·조건(하드웨어·자료)** 을 명시하고 실측과 구분했다.
- [ ] 속도는 자기 하드웨어·설정을 명시해 기록했다. 미측정은 미측정으로 남겼다.
- [ ] 정직성(관측/보간·검증점 독립성)을 별도로 보고했다.
- [ ] R01 on/off 개선폭을 같은 입력·같은 하드웨어로 비교했다.
- [ ] **허용오차·"명확히 우위"의 숫자 문턱**을 대상별로 확정했다 (현재 미정 [O], 05 §9).
- [ ] 위 한계(상용 점수 부재·속도 비교 난이도)를 결과문에 그대로 밝혔다.
- [ ] 재현성: 같은 입력·버전 반복 실행 결과를 허용오차 안에서 일치시켰고, 난수 시드·연산 순서를 고정했다.
- [ ] 결과가 하드웨어(CPU/GPU)가 달라도 동일 메시임을 확인했다(또는 차이 허용오차를 명시).
- [ ] CPU 폴백 경로로 동작하며 특정 하드웨어(CUDA 등)에 묶이지 않음(이식성)을 확인했다.
